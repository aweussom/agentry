# Code audit — 2026-09-23

Baseline: `6d243c3` plus the existing uncommitted Windows/runtime/documentation
changes. The original audit changed documentation only.

Follow-up, later 2026-09-23: the persistent Claude implementation now addresses
A08 (early EOF/result failure and reaping), and Claude-specific cancellation /
disconnect recovery, with offline tests and live acceptance. See
[the implementation record](CLAUDE-STARTUP-2026-09-23.md). Other findings below
remain open; their original line references describe the audit baseline.

## Scope and design decisions

Reviewed the complete production Python server, three backend implementations,
logging module, browser JavaScript/template/CSS, both launchers, dependency and
Git configuration, and existing regression test. Cross-checked README and
roadmap/design records, and inspected the purpose and execution paths of bench
scripts. Historical probes are not a current integration test suite.

The owner explicitly confirmed that **binding to `0.0.0.0` and having no API
authentication are intentional**: the proxy also runs on an always-on office
laptop for LAN clients. They are not audit defects. The service remains a
personal, single-user relay with shared backend state.

Validation used local stubs, mocked processes, extracted JavaScript functions,
and parser checks. No paid model calls, real image generation, production
restarts, credential reads, history rewrites, or dependency upgrades were
performed. Browser event execution and live CLI recovery remain unverified.
This is a source and offline behavior audit, not a dependency vulnerability
scan or certification of external provider behavior.

## Findings

### A01 — High: Markdown artifact links inject main-page event handlers

Location: `static/js/app.js:318`, especially the link replacement at line 348.
Markdown artifacts are inserted directly into the main document at line 303.
`escapeHtml()` escapes text, but does not escape quotation marks for use in an
attribute. The link replacement interpolates an untrusted URL into `href`.

Running the actual extracted `mdToHtml()` in Node on:

```text
[link](https://example.invalid/"onclick="document.title='audit')
```

produced an anchor with a separate `onclick="document.title='audit'"` attribute.
An attacker-controlled/model-produced artifact can therefore introduce event
handler code into the application page. The sandbox on HTML artifacts does
not protect Markdown artifacts. Output generation was reproduced; no malicious
code was executed in a browser. Link schemes are also unvalidated.

Fix: build anchors with DOM APIs or context-correct attribute escaping and a
scheme allowlist. Test quote injection and unsafe schemes in the real renderer.

### A02 — High: Concurrent new chats can run in the same fresh session

Location: `agentry.py:290` and the separate `new_session()`/`prompt()` backend
locks (`backends.py:371`, `backends.py:719`, `backends.py:1040`).

The HTTP layer decides whether a session is fresh and creates it before the
turn obtains its lock. Reproduction: request A creates a fresh session and
pauses before starting its prompt; request B sees `session_fresh=True`, reuses
that session, and completes; A then runs on the same now-used session. A's
independent prompt can see B's context. A deterministic Flask/thread-event
probe produced `B/new/fresh=True`, then `A/new/fresh=False`.

The current regression test uses one fixed stub session ID and does not check
this invariant. Locking session creation and turns separately is insufficient.
Fix: make the reset decision and the corresponding turn one atomic operation,
while retaining independent cancellation and avoiding recursive-lock deadlocks.

### A03 — Medium: Abandoned streams leave backend turns running

Location: `backends.py:740`, `backends.py:1213` and `agentry.py:310`.

Closing a Copilot or Codex prompt generator clears its active queue and releases
the turn lock without cancelling the active runtime turn. A mocked Codex wire
probe started a turn, consumed one delta, and closed the generator; the only
wire request was `turn/start`, with no `turn/interrupt`.

A disconnected client can continue consuming quota. On Copilot, `_on_event()`
routes events to whichever queue is currently active without a turn/session
identity check, so late deltas or idle events can affect a subsequent turn.
Timeout abort is also fire-and-forget, without waiting for terminal completion.
Fix: cancel abandoned turns and establish completion/event ownership before
allowing another turn to consume events. Also clean up work started when a
Codex turn/start acknowledgement never arrives.

### A04 — Medium: Unpinned Copilot defaults become sticky; labels can be wrong

Location: `backends.py:445`, `backends.py:721`, `agentry.py:306`.

When `default_model` or `default_effort` is `None`, a later request omitting that
field does not restore the runtime's initial default after an explicit override.
The real Copilot `prompt()` with an in-memory session retained `model-b/high`
on an omitted-selection request when both defaults were `None`.

Additionally, the HTTP response label is chosen before model switching, and
explicit requests are always labelled with the requested model even if the
runtime reports an org-policy override. `/health` uses Copilot's current session
model, which may be the last override rather than the next request's default.
Fix: retain resolved baseline settings and tie response attribution to the
selection actually applied for that turn. Test runtime overrides as well as
the HTTP argument forwarding that the existing regression covers.

### A05 — Medium: GNU backend flags bypass Windows launcher decisions

Location: `start.ps1:27`, `start.ps1:40`, `start.ps1:96`, `start.ps1:124`.

`--backend codex` is captured in `$Rest`; `$Backend` remains `copilot` during
default-model selection and CLI/auth checks. The extracted real parameter block
reproduced `Backend=copilot`, `Rest=--backend|codex`. Python eventually receives
`--backend codex` but also the Copilot default `--model gpt-5.6-luna`, and the
launcher checks the wrong prerequisites. `--backend claude` similarly gets a
Copilot model unless another model override is supplied.

Fix: normalize all accepted flag spellings before defaults and prerequisite
checks. PowerShell-style `-Backend codex` currently avoids this defect.

### A06 — Medium: Windows Python fallback selects the executable `p`

Location: `start.ps1:45`, `start.ps1:74`.

When `Find-Python` returns `@("python")`, PowerShell unrolls the one-element
array to a string. `$py[0]` then evaluates to `p`, and the slice used for launcher
arguments produces characters. A local function with the same return expression
reproduced `String`, executable `p`, arguments `y|p`. Even forcing an array
requires handling the empty tail explicitly; `1..0` is not an empty range.

This breaks first-run/recreated-venv setup when only `python` is available and
the `py` launcher path is not selected. Fix: preserve array shape and explicitly
construct the optional launcher arguments. Test both discovery paths.

### A07 — Medium: Invalid input and runtime errors violate the JSON API

Location: `agentry.py:239`, `agentry.py:284`, `agentry.py:329`,
`agentry.py:430`, `agentry.py:458`.

Flask test-client requests reproduced HTML 500 responses for a nonempty JSON
array body, `reasoning_effort={}`, a numeric image URL, and an Images request
with `prompt=1`. Those early exceptions also left request-timing entries behind.
A backend raising `BackendError` during a non-streaming prompt likewise yielded
an HTML 500; streaming exceptions can terminate an already-started response.
Other backend failures are yielded as ordinary answer text, so callers can see
HTTP 200 and `finish_reason=stop` for failed generation.

Fix: validate body and field types before backend work, centralize timing cleanup,
map pre-stream failures to structured JSON errors, and define an explicit
streaming failure contract. Test malformed JSON as well as valid JSON with
incorrect types, and failures after partial output.

### A08 — Medium: Claude early process failure becomes an empty success

Location: `backends.py:1566`, `backends.py:1603`.

The stdout EOF sentinel returns normally without requiring a successful result
event or checking process status. A mocked CLI with exit status 1 and no output
produced an empty list of deltas. The HTTP layer then returns empty content with
a normal success response. The result-error path also hides an error when some
text was already emitted. Normal cleanup terminates but does not wait/reap here.

Fix: track the terminal result separately from partial content; distinguish
cancellation, premature EOF and failed completion, and reliably wait for child
process exit. Test failure both before and after partial text.

### A09 — Medium: New Chat during generation repopulates the cleared history

Location: `static/js/app.js:466`, `static/js/app.js:481`,
`static/js/app.js:497`.

The New Chat button and Ctrl+N stay active during generation. `newChat()` clears
the global history and DOM but leaves the request running. Its completion later
pushes the old assistant answer into the new history, even though its message
element has been detached. The next user message is no longer recognized as a
fresh chat by `_is_new_chat()`. Pending attachments and the artifact panel also
survive the reset. This finding is from source review, not a browser replay.

Fix: cancel/reset with a conversation generation ID that prevents stale callbacks
from writing into the new conversation, or disable reset while a turn is active.

### A10 — Medium: Zero image dimensions fail after generation completes

Location: `agentry.py:370`, `agentry.py:531`.

`_size_wording()` accepts `00x00` and other zero-valued dimensions. On receipt
of a valid image, aspect comparison divides by the requested height. A stubbed
successful image turn with `size="00x00"` returned HTML 500 after generation.
Real calls could consume quota before failing to deliver their result.

Fix: reject nonpositive dimensions before starting the backend. Also note that
`n=1` is validated only on input: multiple emitted images are all returned;
the instruction to call the tool once is advisory rather than enforcement.

### A11 — Medium: Persistent runtime death is not propagated promptly

Location: `backends.py:786`, `backends.py:965`, `backends.py:1144`.

Copilot `is_alive()` checks the wrapper's flag and asyncio loop, not the SDK
subprocess. Runtime death does not clear that flag, so `/health` can stay ready
and `_get_backend()` keeps a broken client. Codex checks its process for later
requests, but reader EOF does not wake current pending requests or turn queues;
an active call can wait for its 30/60/900-second timeout rather than fail promptly.
Constructor failures can also leave loop/process/log resources without an
assigned backend to close. These are source-review findings; live process-kill
recovery was not exercised.

Fix: propagate EOF/runtime shutdown to waiters, invalidate backend liveness, and
clean up partial initialization. Test with fake processes rather than production.

### A12 — Low: Each SSE chunk has a different completion ID

Location: `agentry.py:136`.

`_sse()` generates a UUID and timestamp for each chunk, including the final one.
Two consecutive calls reproduced different IDs for what should be one response.
The bundled UI ignores IDs, but clients that correlate chunks can misbehave.
Fix: allocate response metadata once and reuse it throughout the stream.

## Documentation and maintenance observations

- `AGENTS.md` was rewritten to reflect intentional LAN/no-auth operation, real
  session behavior, backend-specific restrictions, and the validation gaps.
- README's account-quota explanation predates the implemented account baseline
  plus local-ledger refresh. Several module/doc comments still describe retired
  ACP transport or all backends as persistent. Codex has no ticker override,
  despite the README promising a Codex console reasoning ticker.
- Only the latest user message is sent to a backend. Client system/developer
  instructions, supplied history and `max_tokens` are ignored. The shared-state
  and cold-Claude constraints should remain explicit compatibility limits.
- An empty Codex cwd plus read-only sandbox and prompt instructions is not proof
  that all built-in reads/tools are disabled. Client-side RPC refusal cannot
  deny operations that execute entirely inside the provider runtime. Preserve
  the intended restrictions without claiming an enforcement guarantee not
  established by the implementation.
- Console logs contain prompt previews, and wire logs include full payloads.
  Logs are ignored, but are not redacted. The existing TODO about previously
  committed `.claude/memory/` is still relevant: history contains those paths.
  No private memory contents were opened and no history was rewritten.
- Dependencies have minimum versions but no lockfile. Windows startup only tests
  importability; Linux startup only installs for a new venv. Neither establishes
  a reproducible SDK version or upgrades an importable outdated environment.
- Quota/rate/model claims are dated local observations, not a current provider
  contract. External pricing and SDK vulnerability status were not audited.

## Validation results and remaining coverage

- All 20 root/bench Python files passed AST parsing; production Python plus the
  changed Copilot probe passed bytecode compilation during the preceding merge
  validation (unchanged by this documentation-only audit).
- `test_agentry_race.py` passed. It covers concurrent model labels, unknown model
  rejection and omitted selection through a stub; it misses A02 and A04.
- Installed dependencies passed `python -m pip check`.
- JavaScript passed `node --check`; PowerShell parsed without errors; Bash passed
  `bash -n` outside the sandbox after its Windows shared-memory setup was blocked.
- Offline reproductions confirmed A01 output injection, A02 scheduling, A03
  missing Codex interrupt, A04 sticky settings, A05 flag binding, A06 fallback,
  A07 error types/timing leaks, A08 EOF handling, A10 division by zero and A12 IDs.
- A09 and A11 were assessed from code. Browser interaction, real CLI tool
  restrictions, provider quotas, Linux execution, and live backend integration
  still require targeted acceptance tests after fixes.

Recommended repair order: A01/A02, then turn ownership/error/liveness handling
(A03/A07/A08/A11), defaults/launchers (A04/A05/A06), and UI/image/SSE edge cases
(A09/A10/A12). Add focused tests with each fix rather than treating the existing
passing smoke test as evidence that these paths are covered.
